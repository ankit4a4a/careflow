# CareFlow Phase 10 — HRM, Payroll, CRM and Notification API

Base path: `/api/v1`. All routes except `POST /hrm/accept-invitation` require the existing JWT authentication and tenant context. Backend RBAC is enforced with Phase 10 permission keys. Branch-scoped users are restricted to their assigned branches; employee self-service endpoints resolve the employee from the authenticated User record and do not trust a submitted employee ID.

## HRM dashboard and employee directory

- `GET /hrm/dashboard` — database-derived employee, attendance, leave, payroll (salary-permission gated), birthday and department metrics plus chart series.
- `GET/POST /hrm/employees` — searchable/filtered directory and employee creation.
- `GET/PATCH /hrm/employees/:id` — employee profile and authorized updates.
- `PATCH /hrm/employees/:id/status` — activate, deactivate, place on leave, terminate or archive with reason and employment history. Inactive/terminated/archived employee accounts are disabled; reactivation restores the linked employee account.
- `POST /hrm/employees/:id/invite` — creates a one-time invitation and sends it using configured SMTP.
- `POST/GET /hrm/employees/:id/photo` — private profile photo upload/download.
- `POST /hrm/employees/:id/documents`, `GET /hrm/employees/:id/documents/:docId/download` — private employee documents.
- `GET /hrm/employee-directory.csv` — branch-scoped CSV export.
- `GET /hrm/profile-requests`, `PATCH /hrm/profile-requests/:id/review` — employee profile update requests and review.

### Employee account invitation

- `POST /hrm/accept-invitation` — public, one-time token acceptance; creates a User with role `employee` using existing authentication. The invitation token is stored as a SHA-256 hash; password hashing uses the existing Argon2 dependency.
- `client/employee-invite.html` — public password setup page.
- Invitation delivery requires configured SMTP. An invitation email is not considered delivered unless the SMTP service accepts it.

## Department and designation

- `GET/POST /hrm/departments`, `PATCH /hrm/departments/:id` — branch assignments, department head, archive/restore.
- `GET/POST /hrm/designations`, `PATCH /hrm/designations/:id` — department, job category, branch assignments and archive/restore.

## Attendance and shifts

- `GET /hrm/attendance`, `POST /hrm/attendance/manual` — daily attendance register and authorized manual status entry.
- `POST /hrm/attendance/check-in`, `/check-out`, `/break-start`, `/break-end` — authenticated employee self-service; timestamps are generated by the server.
- `POST /hrm/attendance/corrections`, `POST /hrm/attendance/:id/correction` — employee or authorized manager correction requests.
- `GET /hrm/attendance/corrections`, `PATCH /hrm/attendance/corrections/:id/review` — correction review.
- `GET/POST /hrm/shifts`, `PATCH /hrm/shifts/:id` — branch-specific shifts, grace periods, time zone, breaks and weekly offs.
- `GET /hrm/roster`, `POST /hrm/roster/assign`, `PATCH /hrm/roster/assignments/:id/cancel` — roster assignments and cancellation.
- `POST /hrm/roster/swap-requests`, `GET /hrm/roster/swap-requests`, `PATCH /hrm/roster/swap-requests/:id/review` — manager-managed shift swaps.
- `POST /hrm/me/roster/swap-requests` — employee's own swap request.

Attendance uniqueness is enforced by tenant, employee, work date and shift. Roster assignment uses a unique per-employee/date lock for non-overlapping shifts; assignments are capped at 366 days and can be renewed. Overnight shift dates are calculated using the configured shift time zone. The worker marks scheduled absences after shift end and skips approved leave, holidays and weekly offs.

## Leave

- `GET/POST /hrm/leave/types` — configurable leave types.
- `GET/POST /hrm/leave/policies`, `PATCH /hrm/leave/policies/:id` — annual allowance, accrual, carry-forward, negative-balance policy, approval levels, holidays and weekly-off rules.
- `GET /hrm/leave/requests`, `POST /hrm/leave/apply` — employee self-application or authorized manager application for an accessible employee.
- `PATCH /hrm/leave/requests/:id/decision` — approval/rejection, including configured approval levels.
- `POST /hrm/leave/requests/:id/cancel`, `PATCH /hrm/leave/requests/:id/cancel-decision` — employee cancellation and manager review.
- `POST /hrm/leave/balances/adjust` — reasoned adjustment with append-only balance adjustment history.
- `GET /hrm/leave/calendar`, `GET/POST /hrm/holidays` — leave calendar and branch/global holidays.
- Employee self-service: `GET /hrm/me/leave-requests`, `GET /hrm/me/leave-balance`.

Leave applications reserve each working date in a unique `LeaveDateLock` collection in a MongoDB transaction. This prevents concurrent overlapping applications and duplicate balance deduction. Partial-day requests are limited to one date and reserve the full date (conservative overlap protection). Monthly accrual runs through the worker and is idempotent per employee, leave type and month.

## Payroll and payslips

- `GET/POST /hrm/salary-structures`, `PATCH /hrm/salary-structures/:id` — configurable earning/deduction components, monthly/weekly/daily frequency and overtime rate.
- `GET/POST /hrm/payroll/runs` — list or generate/resume a draft payroll run for a branch and period.
- `POST /hrm/payroll/runs/:id/review`, `/approve`, `/pay` — draft → reviewed → approved → paid.
- `GET /hrm/payroll/runs/:id/records` — salary-permission-gated record details.
- `POST /hrm/payroll/adjustments` — idempotent, reasoned draft adjustments.
- `GET /hrm/payroll/runs/:runId/records/:recordId/pdf` — released/paid payslip PDF.
- Employee self-service: `GET /hrm/me/payslips`, `GET /hrm/me/payslips/:id/pdf`.

Payroll calculation uses saved salary structures, attendance records, approved paid/unpaid leave, overtime and authorized adjustments. A draft run can be resumed after a partial failure; unique indexes prevent duplicate run/employee records. Finalized runs cannot be modified through draft adjustment routes. Paid status requires an authorized recorded payment reference; this is not a bank confirmation or payment-gateway callback. No payroll journal is automatically posted.

## Reimbursements

- `GET/POST /hrm/reimbursements` — manager view and new claims using the existing Expense collection.
- `POST/GET /hrm/reimbursements/:id/receipt` — private receipt upload/download.
- `PATCH /hrm/reimbursements/:id/review`, `PATCH /hrm/reimbursements/:id/pay` — approval and recorded payment reference.
- Employee routes are listed under self-service. No duplicate Expense or Payment model is introduced.

## CRM and patient portal

- `GET /crm/dashboard`.
- `GET/POST /crm/follow-ups`, `PATCH /crm/follow-ups/:id`.
- `GET/POST /crm/feedback`, `PATCH /crm/feedback/:id`.
- `GET/POST /crm/complaints`, `PATCH /crm/complaints/:id/status`.
- `GET/POST /crm/patients/:id/communications` — communication history; outbound electronic contact respects patient channel preferences.
- `PATCH /crm/patients/:id/communication-preferences`.
- `GET /crm/patient/:id/history` — CRM-safe history only; does not expose clinical notes.
- Patient self-service: `GET/PATCH /patient-portal/communication-preferences`, `POST /patient-portal/feedback`, `POST /patient-portal/complaints`.

## Notifications and automation

- `GET /notifications`, `PATCH /notifications/:id/read`, `POST /notifications/read-all`.
- `GET/PATCH /notifications/preferences`.
- `GET /notifications/outbox`.
- `POST /hrm/notifications/dispatch` — recipient user or role fan-out; requires `Idempotency-Key`.
- Background worker: `npm run worker`. It processes the database outbox, retrying pending/partial/failed items with bounded attempts, performs scheduled reminders, monthly leave accrual and attendance absence marking.
- External email uses existing SMTP configuration. SMS/WhatsApp adapters are not included and are not marked delivered.

## Reports

- `GET /hrm/reports/:type.csv` — `employees`, `department-headcount`, `joining-exits`, `attendance`, `late`, `overtime`, `leave`, `leave-utilization`, `payroll`, `salary-register`, `recruitment`, `appraisals`, `reimbursements`, `crm`, `feedback`, `complaints`, `notifications`.
- Query filters: `from`, `to`, `branchId`, `departmentId`. Salary register and payroll totals require `employee.salary.view`.
- `GET /hrm/employee-directory.csv` — employee directory export.

## Phase 10 permission keys

`hrm.view`, `employee.view`, `employee.create`, `employee.update`, `employee.archive`, `employee.salary.view`, `employee.documents.manage`, `employee.self.view`, `employee.self.update`, `attendance.view`, `attendance.manage`, `attendance.correct`, `attendance.self.view`, `attendance.self.checkin`, `attendance.self.checkout`, `shifts.manage`, `leave.view`, `leave.apply`, `leave.approve`, `leave.self.view`, `payroll.view`, `payroll.manage`, `payroll.approve`, `payroll.pay`, `payslip.self.view`, `documents.self.view`, `recruitment.manage`, `appraisal.manage`, `reimbursement.manage`, `crm.view`, `crm.manage`, `feedback.manage`, `complaints.manage`, `notifications.manage`, `notifications.self.view`, `notifications.self.manage`, `reports.view`.

All sensitive routes enforce backend permissions, tenant isolation, branch scope or employee self-access. Role defaults are extended in `server/src/middleware/auth.js`; custom Role records and user permission assignments remain governed by the existing RBAC system.
